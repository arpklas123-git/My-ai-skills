# code-review

변경 코드를 읽고 근거가 있는 지적을 `critical / major / minor`로 구분한다. 기본은 읽기 전용 리뷰이며 결과는 한국어로 쓴다. 사용자가 다른 언어나 특정 저장소의 CI 기준을 요청하면 그 선택을 따른다.

## 범위와 기준을 고정한다

- PR은 base/head SHA, 변경 목록, 저장소 지침, CI 결과와 리뷰 실패 여부를 확인한다. 로컬 변경은 사용자가 지정한 커밋·범위 또는 작업 diff를 기준으로 삼고 base 브랜치를 추측하지 않는다.
- CI와 같은 리뷰를 요청하면 해당 PR의 caller와 재사용 workflow의 실제 참조 버전을 읽는다. 가능하면 실행 기록의 workflow SHA를 사용하고, 이동 태그의 현재 내용만 확인했다면 그 한계를 밝힌다. 프롬프트·심각도·경로별 제한·추가 지침·출력 양식을 적용한다. 아래 기준은 CI 기준이 없는 경우의 기본값이다.
- CI의 성공 표시만 보고 리뷰 완료로 판단하지 않는다. 모델 실행 실패, 빈 결과, 생략된 통합 테스트와 실제 검증 통과를 구분한다. `verdict`와 `fail-on`/필수 체크에 따른 실제 머지 가능 여부도 구분한다.
- 기본 등급은 변경 행 수 50 미만 `light`, 500 초과 `deep`, 나머지 `standard`다. 문서·lockfile·이미지·생성물은 규모 계산에서 제외한다. 인증·인가·비밀값·migration·워크플로·인프라 변경은 `deep`으로 본다. 사용자가 지정한 깊이나 유효한 CI 수동 레벨이 있으면 우선한다.

| 레벨 | 관점 | 지적 상한 |
|---|---|---|
| light | 크래시·데이터 손상·보안·명백한 버그 중 치명적 문제만 | 3 |
| standard | 정확성·경계 조건·오류 처리·테스트 누락·설계 | 10 |
| deep | standard + 보안·권한·동시성·데이터 손상·복구·호출부/관련 파일 | 15 |

큰 diff를 조용히 잘라 전체를 검토했다고 쓰지 않는다. 주요 변경과 호출부를 나눠 읽고 미검토 범위를 밝힌다.

## 지적은 코드 경로로 입증한다

PR 설명은 의도에 대한 단서다. 실제 diff, 호출부, 입력 계약, 오류 경로와 테스트로 확인한다. 기존 결함을 이번 변경이 만든 결함으로 보고하지 않는다. 테스트가 구현과 같은 가정을 공유해 결함을 놓치는지도 확인한다.

- `critical`: 머지 후 구체적인 입력·상황에서 즉시 장애·데이터 손상·보안 사고·인가 우회를 일으킨다. 그 조건을 적는다.
- `major`: 정상 입력이나 흔한 사용에서 잘못 동작한다. 입력과 호출 경로, 관찰 가능한 결과를 재현 순서로 적는다.
- `minor`: 드문 경계 조건·이론적 위험·선택적 개선. 구체적인 재현 경로를 제시할 수 없으면 major로 올리지 않는다.
- 문서만의 지적은 minor로 제한한다. 실제 비밀값 노출은 critical일 수 있다. 같은 원인은 하나로 묶고, 발견할 지적이 없으면 억지로 채우지 않는다.

코드는 실행하거나 수정하지 않는다. 기존 CI 로그와 테스트 소스를 근거로 읽고, 직접 실행하지 않은 테스트는 통과했다고 쓰지 않는다. 사용자가 재현·테스트 실행까지 요청하면 범위 내에서 수행하고 실행 결과를 별도로 기록한다. 저장소 밖 인증 파일이나 비밀값을 리뷰 자료로 읽거나 게시하지 않는다.

## 결과와 줄별 코멘트

구조화 결과와 게시 양식은 [references/output.md](references/output.md)를 따른다. 지적마다 **PR head 기준 파일·줄 링크, 문제, 재현 조건, 영향과 수정 방향**을 제공한다. 중요한 소스 몇 줄을 인용하면 이해가 쉬워지는 경우만 짧게 보여 주며 비밀값은 인용하지 않는다.

판정은 지적에서 계산한다: critical이 있으면 `blocking`, major만 있으면 `concerns`, 둘 다 없으면 `ok`. `ok`는 GitHub 승인이나 운영 실행 허가가 아니다. 운영 절차만 남았다는 이유로 코드 결함을 만들거나, 코드 문제가 없다는 이유로 운영 검증 완료를 주장하지 않는다.

GitHub 게시를 요청받지 않았으면 채팅에만 보여 준다. 요청받았다면 이미 받은 권한으로 게시하며 다시 묻지 않는다. **승인·머지·라벨·보호 규칙·체크 상태는 변경하지 않는다.**

인라인 게시가 필요하면 Node.js 22+와 인증된 `gh`를 사용하는 [scripts/publish-review.mjs](scripts/publish-review.mjs)를 사용한다. 이 스크립트는 기본적으로 미리보기만 만들며 `--post`를 지정해야 `event: COMMENT` 리뷰 하나에 요약과 인라인 지적을 게시한다. 실행 방법은 output 문서를 읽는다. PR head를 재확인하고 diff의 새 파일 쪽 유효한 줄에만 붙인다. diff 밖·삭제된 파일·patch가 생략된 파일은 요약에 코드 링크와 본문을 남긴다. 네트워크 오류가 나면 중복 방지를 위해 리뷰 목록에서 게시 여부를 확인하고 임의로 재시도하지 않는다.
